# 10. 文档下载、预览、阅读：从文件列表到预签名 URL

## 本章定位

下载/预览的核心不是 gateway 读取文件并返回，而是 file service 做 owner/status 校验后，生成 MinIO presigned GET URL。浏览器再用这个 URL 下载、预览或拉取文本内容。业务授权在 file service，字节传输在对象存储。

总链路：`App 文件列表 -> ApiService.getDownloadUrl/getPreviewUrl -> Drogon FileController -> file_srv Download/Showfile -> MinIOPresignGetURLWithParams -> browser open/fetch`。

这条链路的两个入口 `/file/download` 和 `/file/showfile` 都是普通 POST 路由，挂在 `jwt_decode` filter 之后：

代码证据：`forward_part/gateway/controllers/FileController.h:30-40`

```cpp
	ADD_METHOD_TO(FileController::filequeryinfo, "/file/query", Post, "jwt_decode");
	ADD_METHOD_TO(FileController::filedowm, "/file/download", Post, "jwt_decode");
	ADD_METHOD_TO(FileController::LoadFile, "/file/upload", Post, "jwt_decode");
// ... 省略非关键行，保留完整路径/函数锚点见上文 ...
	ADD_METHOD_TO(FileController::Status, "/file/Status", Post, "jwt_decode");
```

解释：

- 下载/预览接口与其它文件接口一样必须过 JWT 鉴权，用户身份由 filter 注入，不来自前端请求体。
- 注意接口名是"filedowm"（源码如此拼写，与 Go 侧 `Filedowm` 方法一一对应），搜索时不要按 `fileDownload` 找。
- nginx 层为这两个路径各配了精确匹配转发（`forward_part/config/nginx/nginx.conf:148-160`），请求从 `:2024` 直接到 gateway。

## 状态转换

下载/预览链路关心的是文件可读状态，不关心上传任务进度。

```text
pending_scan -> store service 扫描 clean -> success -> file service 允许签 presigned GET URL
pending_scan -> ClamAV FOUND -> infected -> file service 返回 409，前端禁用下载/预览
pending_scan -> 扫描失败耗尽重试 -> scan_failed -> file service 返回 409，等待排障/重试
success -> 用户请求下载 -> attachment presigned URL -> 浏览器下载
success -> 用户请求预览 -> inline presigned URL -> 浏览器打开或前端 fetch 文本
```

前端的 `isFileAvailable(file.status === 'success')` 是 UX 门禁；后端 `file.Status != model.FileSuccess` 是真正安全门禁。两者必须同时存在，因为前端状态可以被绕过。

## 关键数据结构 / 字段

- `FileItem.status`：前端列表判断能否下载/预览的直接依据。
- `FileItem.scan_detail`：感染或扫描失败时展示给用户/排障人员的原因。
- `UserFile.filename + filehash`：file service 查 owner 关系的业务 key。
- `File.object_key`：签 MinIO GET URL 的对象位置。
- `Content-Disposition`：下载用 `attachment`，预览用 `inline`。
- `Resp.Message / download_url / preview_url`：业务 API 返回的不是文件内容，而是短期有效 URL。

## 常见误判与排障顺序

- 误判：下载接口应该返回文件二进制。正确理解：后端只签 URL，对象字节由 MinIO 返回。
- 误判：前端禁用按钮就是安全边界。正确理解：file service 必须再次校验 owner 和 `FileSuccess`。
- 误判：预览等于完整文档解析。正确理解：当前主要是 inline URL 或前端 fetch 文本，复杂文档解析不是当前源码能力。
- 排障顺序：文件列表 status -> 前端按钮门禁 -> Drogon `/file/download`/`/file/showfile` -> file service owner/status 校验 -> MinIO presigned URL -> 浏览器访问/URL rewrite。
